### Shared-file treatment

- **SQL:** retain numbered migration ordering and the `DOCUMENTS` ↔ `DOCUMENT_VERSIONS` circular-FK `ALTER`. Keep pgcrypto. Keep assignment/acknowledgment DDL and tests even though they currently live in the feature migration. Remove only the objects above; `99_drop.sql` must match the final object inventory.
- **Access/RBAC:** `fn_accessible_document_ids` currently reads `DOCUMENT_PERMISSIONS` plus active overrides. Keep/rewrite it without the removed permission catalog. `middleware/auth.ts`, `types/express.d.ts`, `routes/auth.ts`, and routes currently using `requirePermission` must use `requireRole` and document-grant predicates. `DOCUMENT_PERMISSIONS` is kept.
- **Version triggers:** `fn_after_version_approved` currently writes inbox messages; keep its transactionally consistent current-version pointer and superseding behavior, remove those writes. `fn_after_version_expired` exists only to write an inbox message; remove it. `fn_expiry_sweep` should only mark expired versions. Assignment triggers in `05b_triggers_search.sql` exist to write inbox messages; remove them while retaining acknowledgment storage/views. The retire trigger/function uses both removed references and inbox storage; remove them.
- **Break-glass:** `routes/overrides.ts` currently inserts override, flagged log and Admin inbox rows. Keep a transaction inserting override and flagged hash-chained log; the Admin queue is queried from `ACCESS_OVERRIDES` directly. Review remains a separate Admin action.
- **Audit:** retain the immutable hash chain, `verify_audit_chain()` and the audit log screen. Remove history persistence; an endpoint may return `{rowsVerified, result, firstBrokenLogId}` only if approved. `audit_tamper_demo.sql` remains, updated to assert the return value without a history table.
- **Mongo ingestion:** preserve PDF/DOCX extraction and a single `document_contents` row per version with pages/sections/metadata. Remove text chunk splitting and all Mongo `document_chunks` operations. Keep Mongo content compensation and orphan deletion, changing the sweep to inspect only the content collection. `analytics.ts` can remain as a PostgreSQL-authorized Mongo content aggregation if approved.

## 4. Proposed replacement queries and workflows

1. **Recursive CTE:** walk document-version history from a supplied `version_id` to lower version numbers for the same document, with a path array for cycle protection. It relies only on `DOCUMENT_VERSIONS.document_id` and `version_number`; no schema addition.
2. **Nested/correlated query:** use `EXISTS` over `DOCUMENT_PERMISSIONS` joined to the caller's `USERS.role_id` in document-list and expiry queries.
3. **Join/anti-join/aggregation:** retain the version-specific pending acknowledgment anti-join and department completion `GROUP BY/HAVING` query.
4. **MongoDB aggregation:** preserve `document_contents` metadata and run category/page/word/term summaries. API first obtains eligible version IDs from PostgreSQL; aggregation uses `$match`, `$facet`, `$unwind`, `$group`, and `$sort`.
5. **Audit verification:** preserve computation and return an ephemeral result only, if approved. Do not add replacement persistence because no such entity exists in the target model.
